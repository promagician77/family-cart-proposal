Overview

Family Cart MVP

A Chrome extension that sits beside the retailer's cart: assign items to family members, see totals per person, select what to buy, and hand exactly that selection to the retailer's own checkout.

!
Most significant technical risk: Amazon's cart page is undocumented and changes without notice (layout tests, regional variants, identical items merged into one line). The integration must be anchored to stable product IDs, verify every action by reading the cart back, and fall back to a guided mode that never breaks, instead of relying on fragile clicks.

Phase 0 · feasibility

Is Amazon reliable enough to build on?

Three working days. The output is a go / no-go decision backed by measurements, plus a working proof of concept.

Three ways to prepare checkout

Preferred
A · Match the cart's own checkboxes

Amazon's cart lets shoppers tick which items go to checkout. Family Cart sets those ticks to match the selection when the user clicks, then verifies the subtotal. Visible and reversible, and nothing is purchased.

For missing items
B · Add-to-cart link

If a selected item isn't in the cart yet, add it with a standard add-to-cart request by product ID and quantity. Phase 0 checks the method is permitted and stable.

Always works
C · Guided mode

No automation: Family Cart highlights the selected lines and the user ticks them. This is the fallback whenever the adapter's health check fails.

Architecture

Core + retailer adapters

Family Cart's logic never touches a web page. Each retailer is one adapter behind a fixed interface.

Adding Walmart or Target means adding one adapter folder and its fixture tests. Core, UI and storage stay unchanged.
core/adapter.tsthe only contract
export interface RetailerAdapter {
  id: 'amazon-us' | 'walmart' | 'target';
  matches(url: URL): boolean;
  healthCheck(): Health;                // selectors still valid?
  readProductPage(): ProductRef | null;
  readCart(): CartLine[];                // id, title, price, qty
  applySelection(s: Selection): Promise<ApplyResult>;
  capabilities: { checkboxes: boolean; addById: boolean };
}

export type ApplyResult =
  | { ok: true;  verified: { count: number; subtotalCents: number } }
  | { ok: false; reason: 'UNHEALTHY' | 'MISMATCH'; guided: GuidedStep[] };
core/model.tsmoney in integer cents
type Member     = { id; name; order; archived: boolean };
type Occasion   = 'everyday' | 'school' | 'birthday'
                 | 'christmas' | 'other';
type Assignment = {
  id; retailer; productId;                 // e.g. ASIN
  title; priceCents; qty: 1;             // one unit per person
  memberId; occasion?: Occasion;
  status: 'active' | 'purchased'; purchasedAt?;
};

// totals are sums of integers: no 0.1 + 0.2 errors
export const total = (a: Assignment[]) =>
  a.reduce((s, x) => s + x.priceCents * x.qty, 0);

Risks

Specific technical risks

Each risk has a mitigation and gets tested in Phase 0.

RiskImpactMitigation
Retailer layout changeshighID-anchored reading, multiple locator strategies, health check on load, automatic guided mode
Identical items merged into one linehighassignments hold 1 unit each; selection adjusts line quantity and restores the rest
Retailer terms on automationmediumuser-initiated actions on open pages only; strategy C if A/B aren't appropriate
Prices change after assignmentmediumtotals use current cart price; change badge; history keeps paid price
Cart edited elsewheremediumreconcile on every cart view; orphaned assignments flagged, never deleted silently
Dynamic page updatesmediumMutationObserver with debounce; re-read after every retailer update
Service worker shutdown (MV3)lowno state in memory; everything in storage
Web Store reviewlowsingle purpose, minimal permissions, clear privacy policy
